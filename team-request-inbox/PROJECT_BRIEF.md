# 팀 간 업무 요청 인박스 — 프로젝트 브리프

> 이 문서는 Claude Code 첫 세션에 그대로 붙여넣거나, 프로젝트 폴더에 `PROJECT_BRIEF.md`로 저장해 두고 참고하기 위한 것입니다. 같은 폴더에 프로토타입 파일 `team-request-inbox.html`을 함께 두면 "이렇게 동작하면 된다"는 살아있는 명세로 쓸 수 있습니다.

## 무엇을, 왜 만드나

영업 담당자는 외근·운전 중이라 전화나 카톡으로 들어오는 업무 요청을 제때 받지 못하고, 그 사이 요청이 흘러가 버려(읽씹·누락) 일이 샙니다. 이 문제를 해결하는 **팀 간 업무 요청 인박스**를 만듭니다.

핵심 가치는 단 하나, **"요청이 휘발되지 않는다"**입니다. 카톡과 결정적으로 다른 점은 두 가지입니다.
1. 요청이 읽씹돼도 사라지지 않고, 완료될 때까지 목록에 남는다.
2. 잡담과 섞이지 않고 '해야 할 일'만 모인다.

사용자가 미팅을 다녀와 앱을 켜면, 받은 요청이 들어온 순서대로 직관적으로 쌓여 있는 것이 목표 경험입니다.

## 플랫폼

**반응형 웹** 하나로 만든다. PC와 모바일 모두에서 잘 보이게 하고, 모바일에서는 홈 화면에 추가해 앱처럼 쓴다. (네이티브 앱은 만들지 않는다.)

## 추천 기술 스택 (가벼운 MVP 기준)

- 프론트엔드: **Next.js** (React)
- 백엔드/DB/인증/실시간: **Supabase** — 소셜 로그인, Postgres DB, 실시간 동기화를 한 번에 해결
- 알림: **웹 푸시 알림** (Web Push)
- 배포: **Vercel**

> 이 스택은 권장안입니다. Claude Code가 더 나은 대안을 제안하면 함께 검토하세요. 단, "백엔드 직접 구현을 최소화하고 빠르게 배포 가능한 것"이 선택 기준입니다.

## MVP에 반드시 들어가는 기능 (확정)

1. **소셜 로그인** — 카카오 또는 구글 중 하나로 시작. 자체 회원가입/이메일 인증/비밀번호 찾기는 만들지 않는다.
2. **요청 생성** — 입력값: 받는 사람, 요청 내용, 마감일(선택). 보낸 사람은 로그인 정보에서 자동으로 채운다.
3. **받는 사람 인박스** — 들어온 순서대로(최신순) 카드가 쌓이고, 완료 전까지 사라지지 않는다.
4. **상태 관리** — 3단계: `안읽음 / 확인함 / 완료`. 완료하면 인박스에서 내려간다.
5. **보낸 사람용 상태 확인** — 내가 보낸 요청이 지금 어느 상태인지 본다.
6. **알림** — 새 요청이 도착했을 때 웹 푸시 1회. (운전 끝나고 앱을 켜게 만드는 트리거.)
7. **받는 사람 선택** — 가입한 팀원이 목록에 자동으로 뜨고, 거기서 고른다. 부서가 여럿이면 부서별로 묶어서 보여준다.

## 일부러 빼는 것 (MVP 이후로 미룸)

- 개인 스케줄러 / 캘린더 연동 (※ 2단계에서 "요청을 내 일정으로 끌어다 놓기" 형태로 연결 예정 — 지금은 만들지 않음)
- 마감 임박 알림, 미확인 재알림 등 추가 알림 (지금은 '새 요청 도착' 1회만)
- 우선순위 자동 정렬 (지금은 시간순이면 충분)
- 음성 입력, 카톡 자동 수집, 파일 첨부
- 통계 / 리포트

## 한 줄 흐름 요약

> 소셜 로그인 → 팀원 목록에서 받는 사람 선택 → 할 일 던지기 → 상대에게 푸시 알림 → 인박스에 순서대로 쌓임 → 확인·완료 처리 → 보낸 사람은 상태를 실시간으로 확인.

## UI 참고

프로토타입(`team-request-inbox.html`)의 화면 구성과 상호작용을 디자인 기준으로 삼는다. 특히 카드 왼쪽의 상태 색 띠(안읽음=주황 / 확인함=파랑 / 완료=초록)로 한눈에 상태를 파악하는 것이 핵심 UX다. 단, 프로토타입의 임시 저장소(브라우저 내 저장)는 실제 DB(Supabase)로 대체한다.

## 첫 세션에 부탁할 것 (제안)

1. 위 스택으로 프로젝트 초기 세팅 (Next.js + Supabase 연결)
2. DB 스키마 설계 (users, requests 테이블 등)
3. 로그인 → 인박스 → 요청 생성까지 핵심 화면을 순서대로 구현
4. 막히는 설정(소셜 로그인 키 발급, 배포 등)은 단계별로 안내받기
